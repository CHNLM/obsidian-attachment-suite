# Attachment Suite

一个把附件生命周期统一管理的 Obsidian 插件：**本地化外链、统一命名、一致性审计、路径修复、未用清理、ZIP 导出**，全部集成在一个套件里。

桌面端专用（`isDesktopOnly: true`）。

## 功能

| 模块 | 命令 / 行为 | 说明 |
| ---- | ----------- | ---- |
| 媒体本地化 | `本地化当前笔记附件` | 把笔记里的 http(s) 外链图片 / 视频 / 音频 / PDF / 网页以及内嵌 data 图片下载到本地，改写为本地引用。按内容 MD5 去重，支持安全下载（超时、大小上限、类别白名单）。 |
| 统一命名 | `重命名当前笔记附件` | 按「笔记名_类别_序号」规范重命名当前笔记的附件，Obsidian 自动更新链接。可选加时间戳、路径哈希、子类型。 |
| 全库命名 | `重命名全库附件` | 批量按「笔记名_类别_序号」重命名全库所有被引用附件；被多篇笔记共用的附件（共享）为每篇引用笔记复制副本并各自动更新链接。Exclude 目录内笔记跳过。 |
| 本地化 | `本地化全库附件` | 批量扫描全库 markdown 笔记，把 http/data 外链下载到本地附件目录并改写为本地引用；同一外链按内容 MD5 去重仅落盘一份。Exclude 目录内笔记跳过。 |
| 一致性 | `检查库一致性（生成报告）` | 汇总未用附件、坏链接（正文 / 画布 / frontmatter 中指向不存在文件）、需修复的不兼容路径。坏链接列表可按「报告坏链接」设置隐藏。 |
| 路径修复 | `修复不兼容路径` | 把 Windows / macOS / Linux 的保留名、非法字符、超长文件名安全改名并更新引用。 |
| 未用清理 | `清理未用附件` / `清理空附件目录` | 列出未使用附件，按 Obsidian 回收站 / 系统回收站 / 永久删除处理；删除前复检仍需引用者。`清理空附件目录` 会移入不含任何文件的空目录到回收站（含删除后逐层变空的父目录）。 |
| 导出 | `导出当前笔记附件` / `导出未用附件` | 打包为 ZIP 写入库内，附带 manifest 清单；跨目录同名附件自动加时间戳区分。 |
| 收集 | `收集当前笔记附件到归属目录` | 把被当前笔记引用但落在其它目录的附件，移入该笔记的归属附件目录并更新引用。 |
| 笔记移动跟随 | 自动（默认关） | 开启后，笔记跨目录移动时，其相对型附件目录（如 `./assets`）中的对应附件随笔记迁移并保持链接。 |
| 自动化 | 自动（默认开） | 编辑中的笔记一旦出现外链图片（粘贴触发会读编辑器实时内容）或新的附件，自动下载外链到本地并统一命名；按发生变更的笔记处理（不依赖当前焦点，焦点切换不影响）。 |

命令面板可通过中文关键词搜索（如「清理」「附件」「导出」「收集」「全库」「批量」「统一命名」「下载」）。

## 设置要点

- **附件目录来源**（通用）：默认「跟随 Obsidian 设置」，采用 Obsidian「文件与链接 → 默认附件文件夹」的位置；也可切换为「自定义目录」，此时使用下方填写的路径（如 `./assets`、`./attachments`、`.` 或库根下的目录名）。路径支持模板变量：`${notename}`（笔记名）、`${parent}`（上级目录名）、`${parentpath}`（上级目录路径）、`${date}`（当天日期）。本地化与笔记移动跟随都以该有效目录为准。
- **通知级别**：静默 / 仅摘要（推荐）/ 详细，决定操作完成后的提示详细度。
- **本地化类别白名单**：默认全开（SVG 始终不本地化），可按类别勾选是否下载。
- **全局排除目录**：这些目录（相对库根）中的笔记不做本地化、其中的附件不会被判为未使用而清理。
- **命名 / 本地化 / 一致性 / 清理 / 导出 / 自动化**：在「命名」「本地化」「一致性」「清理」「导出」「自动化」分区按各自能力分组配置（另「通用」分区含附件目录来源与通知级别）。命名支持「按类别放入子目录」（`image/`、`pdf/` 等），并可自定义各类型的「类别命名用词」。
- **自动化**：默认开启"自动处理"。粘贴含图片的内容时即触发本地化+命名；被多篇笔记共用的附件会在命名时复制副本，避免某篇笔记的命名约定强加到共享文件。

## 构建

环境要求：Node.js 24.20.0（见 `.nvmrc`）。

```bash
npm install        # 安装依赖
npm run dev        # 开发模式（esbuild watch，输出到 dist/）
npm run build      # 生产构建
npm run typecheck  # TypeScript 严格模式检查
npm run test       # 单元测试（Vitest）
npm run version -- 1.0.1   # 跨文件同步版本号
```

构建产物在 `dist/attachment-suite/`，是**完整可安装包**（`main.js` + `manifest.json` + `styles.css`）。
调试时复制整个目录到库的 `.obsidian/plugins/attachment-suite/`，或：

```powershell
Copy-Item dist\attachment-suite  <vault>\.obsidian\plugins\ -Recurse -Force
```

变更版本统一走 `npm run version -- X.Y.Z`，会同步 `package.json`、`package-lock.json`、`manifest.json` 与 `versions.json`。

## 架构

分层（依赖方向：`infra ← core ← features`，禁止跨功能相互调用）：

- `core/`：零依赖、可单测的纯逻辑（索引、哈希、类型识别、路径兼容、链接改写、安全移动、ZIP、结果模型）。
- `features/`：把纯逻辑包装成可执行块（本地化 / 命名 / 一致性 / 清理 / 导出 / 笔记移动）。多为 `*-core.ts`（纯计算）与同名执行层拆分。
- `infra`（`obsidian-domain.ts` 等）：把 Obsidian `App` 适配为 core 所需接口。
- `settings*`：设置 Schema、迁移、设置面板。

外部资源统一本地化、破坏性操作需预览确认。网络下载只接受 http(s) / data 链接，带路径穿越防护（文件名净化）、大小上限与内容分类净化（如拒绝 SVG，防止脚本注入）。
