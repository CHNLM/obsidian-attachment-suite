# 默认配置设计（开箱即用）

> 目标：**插件放入后即可直接使用**。默认值下 13 条业务命令按下去都要真的干活，
> 用户不需要先读文档、也不需要逐项试错。
>
> 适用前提：插件桌面专用、尚未发布，因此改默认值不需要配置迁移（见 `MEMORY.md`）。
> 本文记录 2026-09-30 这次定稿的取值、理由与常见场景下的实际表现。

---

## 1. 四条设计判据

任何一项默认值先过这四条，过不了就不该是默认：

1. **默认即正确**：命令面板里能看到的命令，在默认配置下按下去必须有结果。
   出现「X 能力已关闭」= 开箱不可用，不可接受。
2. **不替用户做不可逆的事**：破坏性动作要么进回收站、要么必须确认。
   （"默认关闭"不是安全手段——该做的是让它可恢复、可见。）
3. **一个地方说了算**：附件位置跟随 Obsidian 自己的设置。若插件另立一套，
   就会出现"Obsidian 显示放 A、插件却放到 B"，而本仓库最忌讳"显示值 ≠ 生效值"。
4. **少认一种写法 ≠ 安全**：安全边界用**明确的开关**来兜（内网拦截、域名名单、体积上限、
   类别白名单），不靠"假装看不见 HTML 标签"这种隐性限制——那只会让用户遇到
   "我明明有图，跑完却什么都没发生"。

---

## 2. 能力总开关：默认全开

| 能力 | 默认 | 理由 |
|---|---|---|
| 统一命名 | **开** | 它是"附件可读可找"的前提；关掉后本地化的文件会保持原始乱名 |
| 媒体本地化 | **开** | 插件的核心承诺（脱机可用）；不下载的边界另有四道开关兜底 |
| 一致性 | **开** | 只读的体检 + 显式确认的修复；开着不会有副作用 |
| 清理 | **开** | 三重保护：**手动触发** + **删除前确认** + **进 Obsidian 回收站**（可恢复） |
| 导出 | **开** | 只读操作。此前默认关 → 命令面板里两条导出命令按下去只得到「导出能力已关闭。」，典型开箱不可用 |
| 自动处理 | **开** | 插件的主打能力（粘贴即本地化+命名）。两道防线保证它不会静默批量改写：**库就绪门** + **批量护栏** |

## 3. 逐项默认值

> 下表**用简称**（如「轮询间隔」指设置页的「自动处理刷新间隔（秒）」），以设置页上的完整标签为准。
> 需要与界面逐字对照时用 `Attachment Suite/tests/e2e/settings-tab.test.ts` 的守卫口径。

### 3.1 通用

| 选项 | 默认 | 理由 / 不改会怎样 |
|---|---|---|
| 附件目录来源 | **跟随 Obsidian** | 一个地方说了算。插件如实采用 Obsidian「设置 → 文件与链接 → 附件默认存放路径」里的位置，不会背后改用户设置 |
| 自定义附件目录 | `./assets` | 仅在切到"自定义"时生效。`./` 前缀=笔记相对，跟着笔记走、不和笔记混层；也是"移动笔记时附件跟随"能起作用的前提 |
| 通知级别 | **仅摘要** | 既不吵（成功只报汇总），也不会静默掉失败——**失败在任何档位都提示** |
| 详细诊断日志 | **关** | 日志含库内文件路径，属于排查时才开的开关；「代码到底加载没有」已由控制台 info 满足 |
| 全局排除目录 | 空 | 让用户自己圈"这块不动"；空是最不意外的值 |

### 3.2 命名（默认全按"可读 + 可找"取向）

| 选项 | 默认 | 理由 |
|---|---|---|
| 启用统一命名 | 开 | 核心价值：`笔记名_image_001.png` 一眼知道归属与类型 |
| 连接符 | `_` | 跨平台安全、不产生路径歧义 |
| 命名加入时间 | 关 | 名字会变长 14 位；只有"同一笔记频繁新增同类文件"才需要 |
| 命名加入路径哈希 | 关 | 只有跨目录同名笔记才需要，多数人用不上 |
| 名称带类别 | 开 | 一眼分辨 image/video/pdf，是"可找"的关键 |
| 额外带子类型 | 关 | `image_png` 信息更细但名字更长；默认从简 |
| 按类别放入子目录 | 关 | `assets/` 平铺比 `assets/image/`+`assets/pdf/` 少一层；文件多的用户可自行打开 |
| 类别命名用词 | 英文（image/video/…） | 英文短、无歧义、跨系统安全；可逐类改成中文 |

### 3.3 本地化

| 选项 | 默认 | 理由 / 不改会怎样 |
|---|---|---|
| 启用媒体本地化 | 开 | 核心承诺 |
| 本地化网络 URL | 开 | 不下载就谈不上"本地化" |
| **扩展扫描（普通链接与 HTML 标签）** | **开**（本次由关改为开） | 三种写法（md 图片 / 普通链接 / HTML 媒体标签）是同一意图。不认 HTML 写法 → 用户遇到"有图却没被处理"。非媒体外链仍会被类型判定挡下，不会落盘 |
| 用 MD5 作为新文件名 | 开 | 同一张图贴多次只存一份（去重、省空间）；命名开启后随即被改成可读名，MD5 只是过渡态 |
| 拦截内网与本机地址 | 开 | 安全默认：指向本机/内网/保留地址（含云元数据 `169.254.169.254`）的外链一律不发请求 |
| 类别白名单 | 图片/视频/音频/PDF/文档 + `misc` 兜底（**不含网页**；界面只提供前 5 类开关） | HTML 永不落盘、`misc`（其他）不对应任何受管类型，两类都不提供开关，避免"勾了却永不生效"的死选项；默认值里保留 `misc`，只为让这类下载走"跳过非受管类型"的更具体计数 |
| `data:` 图片 | 始终处理 | 不涉及网络请求，没有不处理的理由 |

### 3.4 一致性

| 选项 | 默认 | 理由 / 不改会怎样 |
|---|---|---|
| 报告坏链接 | 开 | 只影响报告展示，纯增益 |
| 修复不兼容路径 | 开 | 命令执行前先列清单、可取消 |
| 路径修复的目标系统 | 仅当前系统 | 平台差异只体现在**两项 Windows 专属规则**上（盘符前缀如 `C:`、`CON`/`PRN` 等保留名）；**非法字符与超长文件名各平台通用**，这一项改不动它们 |
| **笔记移动时跟随移动附件** | **开**（本次由关改为开） | 只对笔记相对型目录（`.`/`./assets`）生效，而这类目录下**不跟随就等于断链**——把笔记拖到别的文件夹后 `![](assets/x.png)` 立即失效。对库根/绝对路径目录它是空操作 |
| 断链修复：相似度推荐 | 开 | 无同名候选时才启用，且**只推荐、由用户选择**，不自动改写 |
| 相似度阈值 / 候选上限 | 0.6 / 5 | 默认值下推荐不会刷屏 |

### 3.5 清理

| 选项 | 默认 | 理由 |
|---|---|---|
| 启用清理 | 开 | 命令手动触发，不会自己跑 |
| 删除方式 | **Obsidian 回收站** | 可恢复，是"默认安全"而非"默认关闭" |
| 排除目录 | 空 | 不猜用户哪些目录重要；确认弹窗会逐条列出待删文件才是真正防线 |
| 排除目录含子目录 | 关 | 与上面配套，语义最窄、最不意外 |
| 删除前确认 | **开** | 关掉它意味着可能误删；文案里已写明风险 |

### 3.6 自动化 / 导出

| 选项 | 默认 | 理由 |
|---|---|---|
| 自动处理 | 开 | 见 §2；仅在"本地化"也开启时才会下载 |
| 轮询间隔 | 5 秒 | 反应够快又不抖；改后失焦立即重装定时器，无需重载插件 |
| 启用导出 | 开 | 只读操作，默认关会留下两条按不动的死命令 |

## 4. 本次调整的三处（含"为什么此前是错的"）

| 选项 | 原默认 | 新默认 | 旧值的问题 |
|---|---|---|---|
| `localize.scanHtmlAndLinks` | 关 | **开** | 用"少认一种写法"当安全手段，代价是用户明明有 HTML 图片却什么都没发生；真正的安全边界在 `blockPrivateHosts`/`allowedCategories`/体积上限 |
| `consistency.followNoteMove` | 关 | **开** | 只对笔记相对型目录生效，关掉它等于"整理笔记 = 图全丢"；这是真实用户最常见的抱怨 |
| `exporter.enabled` | 关 | **开** | 命令面板里按下去只得到「导出能力已关闭。」——比"没有这个功能"更糟 |

三处都做了**变体测试**（把值改回去 → 对应用例转红 → 还原），守卫见
`tests/e2e/defaults.test.ts`。

## 5. 有意保持不变的项（以及理由）

| 选项 | 保持 | 为什么不动 |
|---|---|---|
| 附件目录来源 | 跟随 Obsidian | 改成"自定义"会让 Obsidian 设置页显示的位置与实际落盘不一致——那正是本仓库最忌讳的形态。**改用提示解决**（见 §6） |
| 删除方式 | Obsidian 回收站 | 不改成"永久删除"（不可恢复），也不改成"系统回收站"（跨平台行为不一致） |
| 拦截内网与本机地址 | 开 | 安全默认只应放松、不应收紧 |
| 并发下载数 | 1（串行） | 最稳妥；调大只影响速度，且会增加瞬时请求量与内存占用。用户真的需要时再改 |
| 同主机最小间隔 | 0（不限速） | 单篇笔记的外链数量通常很小，限速无意义；全库本地化属于用户显式发起的大动作 |
| 单文件体积上限 / 超时 / 重试 | 100MB / 30s / 3 次 | 都是"安全兜底"性质，默认值足够宽松，不会挡住正常使用 |
| 域名白/黑名单、仅白名单模式 | 空 / 关 | 名单是"用户知道自己在干什么"时才填的东西；默认空 = 不限制 |
| 自动处理间隔 | 5 秒 | 见 §3.6 |

## 6. 关键处的提示与引导（三处）

1. **设置页最顶部**：明确写"默认设置已按常见做笔记习惯配好：装上就能直接用，**不必逐项调整**"，
   并指出唯一真正需要用户决定的是「附件目录来源」。40 多个选项平铺本身就会给人
   "必须先配点什么"的压力，这段话是开箱即用的第一道防线。

2. **「附件目录来源」下方的动态提示**：当「跟随 Obsidian」且 Obsidian 的附件文件夹是**库根**时
   （这是 Obsidian 的出厂默认，命中率很高），当场提示"附件会和笔记混在同一层"，
   并给出两种可执行的改法（改 Obsidian 一处，或改用 `./assets`）。
   *判定口径与 `effectiveAttachmentFolder` 一致：只有字面 `'/'` 才算库根；
   `attachmentFolderPath` 缺失时会回退到 `./assets`（笔记相对），那种情况不报这个提示。*

3. **「本地化」的「高级」折叠区**：把"设过一次就不用再碰"的网络细项
   （体积 / 超时 / 重试 / 域名名单 / 限速 / 并发 / 最小文件大小）收进 `<details>`。
   收起**不影响任何行为**，默认值照旧生效；只是让常用项留在视线内。

## 7. 常见场景下默认配置的具体表现

### 场景 A：新建库，第一次粘一张网页图片
粘贴 → `editor-paste` 事件 → 剪贴板 HTML 转 Markdown → 判定为外链图片 →
**自动下载 + 保存 + 统一命名**（在**下一次轮询周期**内完成——默认间隔 5 秒；右上角一条汇总通知）。
落点：若 Obsidian 附件文件夹是 `./assets` 之类 → 笔记旁的 `assets/`；
若是库根 → 库根（**设置页会提示你改**）。
不做什么：启动期不做任何事；一次标脏超过 5 篇时**整批拒绝**并明确告知（防"打开 Obsidian 就批量改写"）。

### 场景 B：从网页剪藏一篇文章（含图、含普通链接）
外链图片被下载并改写为本地路径；`<img>`/`<audio>`/`<video>` 标签也一并识别（扩展扫描默认开）；
**指向网页的普通链接不会被下载**——类型判定会把它归到"网页"并跳过，所以不会把别人的整站抓进库里。

### 场景 C：整理笔记目录（把笔记拖到别的文件夹）
若附件目录是笔记相对型（`./assets`），**附件一并迁移、引用保持可用**；
若是库根或绝对路径，附件不动（也不该动）。

### 场景 D：库乱了，跑一次大扫除
1. 「检查库一致性」→ 报告列出未用附件 / 断链 / 不兼容路径，断链行可点击跳到笔记里那一处；
2. 「收集全库散落附件」→ 把散落在各处的附件归到各自笔记的归属目录；
3. 「重命名全库附件」→ 统一为 `笔记名_类别_序号`；
4. 「清理未用附件」→ **先弹确认框逐条列出待删文件**，确认后进 Obsidian 回收站（可随时恢复）。

### 场景 E：发现某条链接挂了
「修复断链」→ 精确/归一化/URL 解码能确定的自动改；大小写差异与多候选**进交互层让你选**，
绝不替你猜；无候选的保持原样并留在报告里。

### 场景 F：想给别人一份附件包
「导出当前笔记附件（zip）」→ 在笔记同目录生成 `<笔记名>_Attachments.zip`（含 manifest）；
「导出未用附件」→ 在库根生成 `Unused_Attachments.zip`。默认可用，不需要先去设置里开开关。

## 8. 默认"不做"的事（诚实登记）

- 不会因为插件启动而改写任何文件（库就绪门 + 批量护栏，见 `docs/coverage-audit` §10）；
- 不会下载 HTML 网页、也不会把普通网页链接抓成本地文件；
- 不会下载指向本机/内网/保留地址的外链；
- 不会自动修复"无候选"或"多个候选"的断链；
- 不会永久删除任何东西（默认走回收站，且删除前必须确认）；
- 不会改名不在笔记中被引用的附件（孤儿只出现在报告/清理清单里）。
